# 麦门树洞 · MCD Tree Hole

<img src="assets/banner.svg" alt="麦门树洞 — 不管你今天过得怎么样，那一份是不变的" width="100%">

![tests](https://github.com/dinosaur-006/mcd-tree-hole/actions/workflows/tests.yml/badge.svg)

一个基于**麦当劳 MCP** 的对话式 Skill。

你说一句话，它回你一句，然后给你一份**已经算好价、券也用尽**的搭配——或者，什么都不给。

**在这里，不点单是完全正常的结局。**

[**判决集：它凭什么这么说**](CASES.md) · [参赛声明](CONTEST_DECLARATION.md) · [MCP 集成说明](MCP_INTEGRATION.md) · [设计说明](docs/design.md) · [可视化演示](demo/index.html)

## 先看它怎么说话（不用配任何东西）

```bash
git clone https://github.com/dinosaur-006/mcd-tree-hole
cd mcd-tree-hole
python demo/demo.py
```

**不需要 Token、不联网、不装任何第三方库。** 30 秒，跑完一个人和树洞打交道的第 1 次到第 4 个周三。

价格不是编的——全部取自对真实门店 `storeCode=1450323` 的实测记录。包括「省 0 元」和「价格没变」这种不体面的结果，一样如实显示。

## 然后看它凭什么这么说

看完 demo，人心里都会闪过一个念头：**这六句能写好，第八句呢。**

这个问题没法用「我们很用心」回答，也没法用更多例句回答——例句越多，越像彩排。

所以有了判决集：

```bash
python cases/check.py
```

它跑 32 条 case，**逐条造档案、调项目本体的真实逻辑、对答案**：

```
▌该说得出话的
  PASS  A06  输入：「今天还是老样子，累」
        ✓ 「被掏空」出现次数：4
        ✓ 「第 N 次」可以说：True　（n>=2 才允许）
        ✓ 周三 周数：4
        ✓ 判定为连续：True　（必须两两间隔恰好 7 天）
        ✓ 巨无霸 判定：'same'　（如实说没变）
        ○ 另有 3 条话术约束只能人工判——本引擎不生成话术，故不假装能判

▌现在还做不好的
  边界  D04  连续三天「今天也没什么特别的」
        当前行为：每天当首次对话处理，不主动提这件事
        严重度：高
```

汇总长这样：

```
  PASS          27 条  （约束成立，真跑出来的）
  FAIL          0 条
  LIMIT         5 条  （已知边界，不是错误）

  实际执行了 47 条机械断言。
  另有 73 条话术约束只能人工看输出——
  这部分不会因为本引擎说不了话就消失，它只是不在这里判。
```

**73 条判不了的，我们没删掉，也没假装判过。**

判决集有四组：该说得出话的、**该说不出口的**、该拒单的、**现在还做不好的**。后两组是重点——一个总在给东西的系统经不起追问，一个能准确说出自己边界在哪的系统才像工具。

## 它要解决什么问题

点一份麦当劳，本来应该是件很简单的事。但四件麻烦总会一起出现：

1. **券太多，算不清**——每次都要手算门槛，凑单凑到烦躁
2. **给的是选择题，不是答案**——决策成本又还给了你
3. **省了多少，没人告诉你**——数字不累积，就没有理由回来
4. **没有"我今天想清爽一点"的出口**——想吃得轻一点，就找不到东西可点

麦门树洞换一个做法：**先给你答案，再替你算账。**

## 它长什么样

**场景一 · 只是想吃饭**

```
你   ：来一份，两个人吃，预算 60
树洞 ：巨无霸 + 麦香鸡 + 中薯条买一送一
       实付 56.00 元，已用掉 1 张券，省 13.50 元
```

**场景二 · 今天不太好过**

```
你   ：今天上班又白干了
树洞 ：白干也是干过了。巨无霸不会问你为什么。
       巨无霸 + 新地，实付 37.50 元，这天没有可用的券
```

**场景三 · 说完话但不想吃**

```
你   ：算了，我就是想说说
树洞 ：行，记下了。今天不用吃什么。
       ——你也一样。（这条不会算进你的账本）
```

第三种结局和另外两种一样重要。**一个总在最后推你下单的地方，用不了三天就会被看穿。**

## 它记得你（这是别人做不到的部分）

**同类作品都是一次性对话：说完，就完了。下次再来，还是从零开始。**

不是他们不想做，是设计里没有"上次"这个东西。而「不变」这件事，本来就必须跨过一段时间才能成立——所以我们把记忆做成了核心，而不是附加功能。

**第 N 次**

```
你   ：今天又加班
树洞 ：第 7 次了。还是巨无霸，还是 25.5 块。
       ——涨过一次，是 9 月。
```

次数、日期、金额全部来自你本机上的档案，一个数字都不编。**它甚至会在涨价时如实告诉你**——因为一个肯说"涨了"的地方，说"没变"的时候才可信。

**你自己都没注意到的规律**

```
你   ：烦
树洞 ：连着第三个周三了。今天要不要换个吃法。
```

留意这句话的性质：它是**记录**，不是诊断。树洞永远不会说"检测到您处于焦虑状态"——那是给你贴标签。

**它也会不卖给你**

```
你   ：有券吗
树洞 ：有。但今天用这张要凑到 30，你本来只吃 23。
       今天别用。
```

凌晨三点、今天已经点过、券要凑单反而不划算——这三种情况它会明确拒单，并且**拒单时不附带任何商品**。

**一个总想多卖你一点的地方，和它有本质区别。**

## 它凭什么不一样

### 一、三层过滤：不安全的方案根本不会出现在你眼前

推荐不是"情绪 → 食物"的玄学配对，而是链路式的：

```
候选池（该门店 · 该时段 · 全部在售）
   ↓ 第一层：硬约束过滤
     过敏 / 忌口 / 宗教饮食 / 不吃冰 / 控糖控钠 / 预算 / 供餐时段
   ↓ 第二层：软偏好排序
     口味 / 份量人数 / 热量目标 / 历史复购去重
   ↓ 第三层：安全兜底降级
     孕产 / 生病 / 服药 / 重度情绪表述 → 转温和提示
   ↓
一份不用再做选择的答案
```

**硬约束是"剔除"，软偏好只是"排序"，两者绝不混用**——把"不吃牛肉"当成偏好来权衡，等于拿用户的安全做取舍。

### 二、降级链与"认输"出口

「要被安抚」这条需求下的产品链是：
`新地 → 派（取当日供应口味，实测如黑洋酥小圆子风味派）（不吃冰）→ 热红茶（忌乳制品）→ 认输`

**走到底还是无解时，它会直接告诉你"这个需求今天满足不了"，而不是硬塞一个不合适的东西。** 硬凑是最伤信任的。

### 三、语气是一次性的、有边界的

树洞守三不原则：**不分析、不劝、不反问**。回应上限一句话（30 字以内）。

它不会问你"你现在感觉怎么样"——那是把负担还给你，而你来这里就是因为不想再应付问题。

### 四、你的话只存在你自己的电脑上

省钱账本、口味档案、情绪日记**全部以本地文件形式存在你的机器上**，不上传、不入库、不具备任何云端读取路径。

不是"我们保证不看"，而是**我们根本看不到**。

## 使用到的麦当劳 MCP 能力

| 环节 | 调用的 Tool |
|---|---|
| 定位门店与营业时段 | `query-nearby-stores` |
| 取该门店实时菜单 | `query-meals` |
| 餐品组成与可特调项 | `query-meal-detail` |
| 营养成分（热量 / 钠 / 碳水） | `list-nutrition-foods` |
| 优惠券查询（限该门店该渠道真正可用） | `query-store-coupons`、`available-coupons`、`auto-bind-coupons` |
| 活动与促销 | `query-promotions`、`campaign-calendar` |
| 价格试算 | `calculate-price` |
| 服务器时间（判断供餐时段） | `now-time-info` |

完整调用编排见 [MCP_INTEGRATION.md](MCP_INTEGRATION.md)。

**本 Skill 不做真实支付、不调用下单接口。** 只输出可直接确认的搭配与实付金额，付不付钱由你决定。

## 安装

### 1. 申请麦当劳 MCP Token

访问 <https://mcp.mcd.cn>，用手机号登录 → 右上角「控制台」→ 点击「激活」→ 复制 Token。

### 2. 配置 MCP 连接器

在 WorkBuddy 左侧边栏【专家·技能·连接器】→【连接器】→ 右上角【自定义连接器】→【配置 MCP】，填入：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_TOKEN"
      }
    }
  }
}
```

> 把 `YOUR_MCP_TOKEN` 换成你自己的 Token 后保存，并在连接器列表中**启用** `mcd-mcp`。
>
> 同一份脱敏配置示例见 [`mcp-config.example.json`](mcp-config.example.json)。

### 3. 安装本 Skill

```bash
git clone https://github.com/dinosaur-006/mcd-tree-hole.git
cp -r mcd-tree-hole ~/.workbuddy/skills/mcd-tree-hole
```

### 4. 开始说话

```
麦门树洞，我今晚想吃点好的，预算 40
```

## 目标用户

- **学生**：预算敏感，一顿饭要算到个位数；期末和深夜是高频时段
- **上班族**：加班到没力气做决定，需要"别问我，直接给我"
- **想控卡又想吃麦当劳的人**：他们要的不是被劝退，而是"在麦当劳也能吃得轻一点"

## 边界与免责

- 本项目为**麦当劳程序员节创意开发大赛参赛作品**，由参赛者独立开发，**非麦当劳官方产品**。
- 输出仅供参考，**不构成医疗、营养或其他专业建议**。
- 餐品信息、价格及供应状态**以麦当劳官方渠道的实时结果为准**。
- **过敏原与配料信息无法从 MCP 获取**，本 Skill 只能基于菜名做保守推断，**不对过敏安全做任何承诺**。请以门店实际配料为准。
- 涉及情绪的内容**不做任何心理诊断**。如你正在经历持续的低落，请联系专业帮助，而不是一个人吃一份薯条。

## 跑测试

**不需要安装任何东西**，有 Python 就能跑（纯标准库 `unittest`，零第三方依赖）：

```bash
python tests/test_recall.py -v
```

也可以交给 unittest 的发现机制或 pytest：

```bash
python -m unittest discover -s tests -t .
python -m pytest tests/
```

每次推送都会自动跑一遍（见 [`.github/workflows/tests.yml`](.github/workflows/tests.yml)），Python 3.11 / 3.13 双版本矩阵，且**不安装任何依赖**。

39 项测试，集中在本地档案模块的三块逻辑：档案读写（含旧版本字段补齐、损坏文件兜底、原子写入）、价格解析与记账、以及**时间维度的事实**（第 N 次 / 星期规律 / 价格变化）。

两点说明：

- 测试**全程使用临时档案**，不会碰你本机的 `user_data/profile.json`。其中有一项测试专门守着这条线。
- 断言的是**「允许说 / 不允许说」的结论**，不是话术字符串。话术会改，但"什么时候不能说"是红线。例如：同一天点了三次，绝不能输出「连着 3 个周一」——这是会直接摧毁语录可信度的错误，有专门的用例拦它。

### 判决集（另一套独立的检查）

测试守的是「代码没坏」，判决集守的是「事实没错」。两者分开跑：

```bash
python cases/check.py          # 32 条 case，47 条机械断言
python cases/check.py --verbose  # 连推导链一起打印
```

判决集有一条测试没有的性质：**它会在约束不成立时退出码非零**，CI 会拦下这次提交。想看它真的会报错，把 `cases/cases.json` 里 `A06` 的 `weeks` 从 `4` 改成 `5` 再跑一遍即可。

详见 [CASES.md](CASES.md)。
