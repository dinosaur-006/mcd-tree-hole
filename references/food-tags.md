# 菜品标签表

供第一层**硬约束过滤**使用。命中任一用户禁忌即从候选池剔除。

> **重要限制**：麦当劳 MCP 的 `list-nutrition-foods` 只返回能量、蛋白质、脂肪、碳水化合物、钠、钙 8 个字段，**不提供过敏原与配料表**。
>
> 因此本表标注**基于菜名语义与公开营养成分的保守推断**，用于筛选而非担保。
> **本 Skill 在任何情况下都不对过敏安全做承诺**，输出时必须提示用户以门店实际配料为准。措辞见 `guardrails.md`。

> **标注优先级（实测确认，优先于本表）**：`query-meals` 在 **`data.categories[].meals[].tags`** 返回餐品标签。
>
> ⚠️ 它**不在** `data.meals.{code}` 明细表里——后者只有名称、图片、价格与优惠类型字段。**按明细表找标签会误判为"官方没有标签"。**
>
> 实测见过的标签分两类：**品类语义**（`100%纯牛肉`、`100%安格斯牛肉`、`麦香鱼系列`、`冰淇淋`、`派`、`冷饮`、`热饮`）可直接驱动硬约束；**营销语义**（`上新`、`爆款`、`人气`、`麦金卡`、`限定特惠`、`经典精选`）不参与过滤，需主动排除。
>
> 因此判断顺序是：**① 官方 tags → ② 本表 → ③ 菜名关键词**。
>
> 本表的作用是给**没有标签**的餐品兜底，以及补充官方标签未覆盖的维度（如咖啡因、麸质、是否含冰）。官方菜单会随季节变化，请定期对照 `query-meals` 的实时返回校对。

标签含义：`牛` 牛肉 · `猪` 猪肉 · `禽` 鸡肉 · `鱼` 鱼类 · `蛋` 蛋类 · `乳` 乳制品 · `麸` 含麸质 · `辣` 辣 · `冰` 冷食或冷饮 · `咖` 含咖啡因

## 六、预算分档（复用官方口径）

`query-meals` 的官方描述中已内置企业团餐的搭配规则，**本项目直接复用，不另创一套**：

| 预算 | 搭配 |
|---|---|
| 20 元以下 | 小食 |
| 20–30 元 | 汉堡 + 小食，或 汉堡 + 饮料 |
| 30–40 元 | 汉堡 + 薯条 / 小食 + 饮料 |
| 40–50 元 | 汉堡 + 薯条 + 小食 + 饮料 |
| 50 元以上 | 丰富组合，优先不重复小食 |

## 七、维护说明

- 官方菜单会随季节与门店变化，**本表需随 `query-meals` 的实时返回定期校对**
- 新增菜品时先打标签，未打标签的菜品**默认不进入推荐**（宁可少推，不可推错）
- 所有标签仅为保守推断；**任何涉及过敏的判断都必须附带免责提示**
