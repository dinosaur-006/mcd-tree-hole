# 设计说明

本文件记录「麦门树洞」的设计决策依据。**它主要写给评审，也写给未来的维护者。**

---

## 一、定位

> **不管你今天过得怎么样，麦当劳那一份是不变的。**

### 为什么是这个定位

最初的方案是"难过时来倾诉的地方"。这个定位有一个战略级问题：**麦当劳的品牌主场是"欢乐、家庭、陪伴"，不是负面情绪。**

"麦门文学"是**用户的二创**，官方乐见其成甚至借势，但不会愿意把品牌主场变成情绪垃圾桶。品牌方的真实顾虑会是：万一有人在里面表达严重情绪怎么办？被写成"麦当劳把情绪消费化"怎么办？

转向的契机在原始语料本身——"……但这并不影响我吃麦当劳"。**这句话的重点在后半句**：不是"我很难过"，而是"有个东西是不变的"。

于是定位改为「**不变的那一方**」：

- 开心也来，难过也来，单纯想吃也来
- 它不说教、不安慰、不评判，只是**那一份东西没变**
- 品牌调性保住了，梗也没丢

### 我们不做什么

- ❌ 不做情绪出口，不做心理支持产品
- ❌ 不做社交产品，不产生任何他人可见的内容
- ❌ 不用"难过 → 吃东西"建立因果（情绪是**选择依据**，不是消费理由）
- ❌ 不做营养或医疗建议

## 二、骨架：先是一个好用的点餐助手

**情绪是灵魂，但不能当主入口。**

原因很直接：**情绪是低频的。** 人不会每天都有情绪要倾诉，但有情绪才打开，等于留存模型是假的。

因此：

| 层 | 承担什么 | 频次 |
|---|---|---|
| 点餐助手 | 骨架、主入口 | 每天可用 |
| 情绪加层 | 差异化、记忆点 | 偶尔触发 |
| 省钱账本 + 券到期提醒 | **留存主力** | 每天都有价值 |
| 情绪日记 | 情感沉淀 | 不承担留存 KPI |

**双入口**：「我有话说」/「我就要吃饭」。不强迫任何用户走情绪流程——因为留存的前提是先能被用上。

## 三、推荐机制：三层过滤

```
候选池（该门店 · 该时段 · 全部在售）
   ↓ 第一层：硬约束过滤 —— 剔除，不权衡
     过敏 / 忌口 / 宗教饮食 / 不吃冰 / 控糖控钠 / 预算上限 / 供餐时段
   ↓ 第二层：软偏好排序 —— 仅改顺序
     口味倾向 / 份量人数 / 热量目标 / 历史复购去重
   ↓ 第三层：安全兜底降级 —— 转温和提示
     孕产 / 生病 / 服药 / 重度情绪表述
   ↓
一份不用再做选择的答案
```

### 为什么硬约束与软偏好必须分层

如果"不吃牛肉"和"口味偏咸"进同一个打分函数，系统就有可能为了凑合口味而输出含牛肉的方案。

**安全约束不进评分函数，只做集合剔除。** 这是设计红线。

### 为什么中间要有"感官需求"层

映射不是"情绪 → 食物"，而是三段式：

```
情绪  →  它真正需要的感官体验  →  承接它的产品
```

- **可解释**：能说清为什么给这一份，而不是随机配对
- **可维护**：需求层稳定，产品层随菜单变化替换
- **可降级**：用户不吃冰时，不必重做映射，只需在"要被安抚"下换一个承接产品

### 「认输」出口

降级链走到底仍无解时，**如实告知用户这个需求今天满足不了**，不硬凑。

硬凑一个不合适的东西，比承认给不了更伤信任。

## 四、语言：语录的句式公式

```
承认坏  →  但有个东西不变
```

**前半句「承认」**：把处境平铺出来，不评价、不打气。
**后半句「锚点」**：陈述一个事实层面的不变。

这个公式之所以站得住，是因为它**不做安慰**。安慰是假的——"一切都会好的"用户自己都不信。而"薯条还是脆的"是一个事实。**这是唯一一种不显得轻浮的陪伴。**

### 人格约束：三不原则

**不分析、不劝、不反问。** 回应上限一句话（≤30 字）。

最毁体验的是像心理咨询师一样问"你现在感觉怎么样"——那是把负担又还给了用户，而用户来这里正是因为不想再应付问题。

### 关于版权

**全部语录自创**，未引用或改编麦当劳官方微博、广告或任何第三方文案。

参赛声明的「原创性声明」要求原创开发，因此本设计选择**模仿文体而非复制文本**的方式承接"麦门"的语言气质。

> 有意思的佐证：官方自己的营养数据里就有 `nutritionDescription` 字段，填的是"能量约清水1杯""能量约鲈鱼1条""能量约猕猴桃2个"。**口语化类比本来就是麦当劳官方的话术气质**，与本项目同源。

## 五、存储与隐私

档案（账本 / 口味 / 情绪日记）**全部以本地文件形式存在用户本机**。

本地存储起初是"退而求其次"，但它与产品调性恰好是一件事：用户半夜说的那些话，**只存在他自己的电脑上，服务端看不到。**

这句话可以同时解决三件事：隐私顾虑、合规风险、以及"我凭什么信你"的信任问题。

**"我们没法看你的记录"比"我们保证不看你的记录"强得多。**

代价是档案不跨设备。这是隐私设计的成本，也是承诺本身。

## 六、主动让步的部分

以下不是遗漏，是**有意为之的边界**：

| 让步 | 原因 |
|---|---|
| 不做过敏安全承诺 | MCP 的 `list-nutrition-foods` 不提供过敏原与配料表，只能基于菜名保守推断 |
| 不调用 `create-order` | 真实下单属于用户的高信任决策，且每次验证都产生花费；交付止于"可直接确认的搭配与实付金额" |
| 不做营养 / 医疗建议 | 参赛声明「使用提示」明确：项目输出不构成医疗、营养或其他专业建议 |
| 不给用户贴情绪标签 | "检测到您处于焦虑状态"会立即摧毁信任 |
| 情绪识别模糊时不猜 | 回到用户原话 + 一句中性回应 |
